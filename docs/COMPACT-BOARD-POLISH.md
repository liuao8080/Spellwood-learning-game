# 紧凑战场与人物近景

基线为4.1.0-alpha.1提交6d7bb94，浏览器run37812725771全部16场景通过。本分支为4.1.0-alpha.2候选；在新的实际截图和交互验收前，不继承基线的视觉通过结论。

## 已观察的问题

基线320×568原图中，手牌约180px、操作区约115px，能看见的棋盘约105px高。文字与44px控件清楚，但模型和空间明显被压缩。此前只看空场助力界面不足以证明满场可用。

独立审查20款真实WebGL衣橱图还发现：单人近景被强制使用低细节，底座没有正常受光，持续的CSS椭圆会分散对脚底接触的注意力。晶石配件与衣物使用相近的表面响应。

## 候选修改

- 650px以下短竖屏合并回合、剩余时间和轮到谁的提示，保留双英雄生命/能量。音乐仍可在设置中调整，省去重复快捷按钮。卡牌高度不减
- 此尺寸下手牌使用既有滑动、滚轮与键盘路径，操作标题显示张数与滑动提示，去掉挤占行动栏的独立分页按钮。五项行动占据整行，每个仍至少44px；画布的CSS设计高度在320×568为198px，实际可见棋盘大小以截图为准
- 仅WebGL单人物衣橱使用已有中等细节，CPU预览和对局人物仍采用原低档。底座使用现有灯光的粗糙实体材质，静止时不显示装饰椭圆，揭晓时保留短脉冲
- 晶石锤、冠饰和肩饰进入既有accent材质批次；几何、颜色与三个材质批次数保持，不添加透明层

## 验证方法

首次候选422043a的run37820070102在740×360满场失败：四列双方标签相交约2.17px，近排距手牌不足1px。注册和详情流程通过，后续14场景未执行，不能继承旧版结果。21件原始截图/JSON与日志已经取回，失败仍保留。

修正版短横屏在原手牌尺寸不变的情况下，将场景向上拓展24px，回合信息收进单行顶栏。短横屏相机俯视角与实体棋位深度同时调整，标签保留两行完整点击空间；棋盘落位圆环和人物位置随布局变化，不只移动文字。紧凑人物换皮后仍保留对应席位。几何检查与离线CPU像素用于早期排错，最终以此提交的真实浏览器满场图验收。

新增第17个真实双浏览器流程：通过界面建立合法低费伙伴牌组，由普通服务端洗牌，两侧自然召唤至四位伙伴。实际检查桌面、844×390、740×360、390×844与320×568的八个标签、英雄生命/能量、手牌和控件；空场不能满足条件。

自然抽至七张后，用真实滚轮遍历重叠手牌窗口，并以Chromium触摸事件平移，检查没有选牌或花费。原16个流程保留，场上详情和满场布局在完整对局套件之前单独执行，不重复计数。

人物沿用相同相机和灯光，以前后CI同款原图判断细节和受光的实际收益。所有人物切换后只保留一个活动模型，CPU与WebGL质量档分别记录。持续帧率、物理手机和公网部署仍是独立验收项；图片不会证明这些项目完成。

大部分功能验收主动开启减少动态，证明的是操作和结算安全。不能把这些通过结果称为普通速度攻击动画已经通过审美验收；普通动态需另看连续动作证据。

第二轮run37858926286已取得五种满场视口和七牌滚轮/触摸证据。740×360两行标签相隔约33.41px，近排距手牌约6.20px；844×390分别约51.84px与10.57px。唯一失败为320px标签的DOMRect浮点高度43.999984px；修正同时要求布局高度至少44px和投影几何误差不超过0.001px，不缩小实际目标。该轮仍为失败，后续14项未跑，不能称整套通过。

未参与实现者实际复核五张原图，确认大手牌和横屏标签改善，也指出竖屏左前英雄被第一单位标签盖住、短横屏英雄过小。此人物展示缺口仍开放，不能以功能绿灯替代审美验收。
