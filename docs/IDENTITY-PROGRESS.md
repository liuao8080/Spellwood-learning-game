# 游客、账号与进度

此说明对应4.1.0-alpha.1开发分支。现有公开4.0.0-alpha.2电脑试玩没有接入这些在线账号功能。

## 身份与恢复

首次网页访问通过 POST /api/identity/guest 获得随机游客，HttpOnly SameSite=Lax Cookie 保留浏览器身份。HTTPS origin 使用 Secure 和 __Host- Cookie 前缀。Guest有效期365天，账号会话30天；过期后游客不保证可恢复，账号可重新登录。没有硬件指纹、邮箱、真实姓名、年龄或社交登录。

用户名只接受英文字母，1字母也合法，大小写不区分；请求保护上限4096字节。密码按Unicode字符计数，至少6个，不裁剪空格或增加字符组合要求；请求长度有安全上限。异步scrypt默认N=32768,r=8,p=3，每个密码独立随机盐，最多2个同时计算。登录/注册/恢复均有短期限速。

注册直接升级当前游客，保留playerId。登录另一个账号不把原游客的数据合入对方，退出后可以回到未绑定原游客。账号恢复需要用户名、恢复码和新密码，并撤销该账号其他会话。恢复码只在相关操作完成时显示一次，关闭面板即清除显示；新码使旧码失效。没有密码也没有恢复码时，不能依靠个人问题找回。

## 进度的权威来源

数据库保存玩家资料、单份schema4进度和幂等事件摘要。事务同时提交数据、revision和回执。学习由服务端判题生成；战绩由服务端终局生成；客户端不能提交correct、比分、奖励余额或抽卡结果。

- 学习事件：learning:<challengeId>
- 战绩事件：result:<roomId>:<seat>
- 学习日参与：participation:<challengeId>，服务器检查从签发起累计至少3.2秒，并有至少1.2秒前台反馈；资格保存于首次满足条件的可信时间；只计真实已答回执，答错也可参与
- 设置、礼盒、导入使用一个稳定requestId；未知结果先确认原请求，不换ID重抽
- 卡牌礼盒10张、人物造型1件或10件结果在动画前事务保存，体验钱包与正式钱包隔离
- 每日任务和五日礼盒同一参与事务推进，以签发日归属；人物装备在进入房间时冻结
- 客户端每次进度请求声明预期playerId，服务端先与Cookie身份核对。POST缺失/不符即拒绝，防止旧页误写新账号

数据库暂时写失败时不显示“已保存”，当前进程保留待提交的学习/战绩并重试，新学习与匹配等待同步。这个内存待提交队列不承诺能跨进程崩溃恢复；已经提交的数据库数据可跨正常重启保留。

## 导入旧记录

支持校验旧schema1、schema3和当前schema4备份；没有定义的schema2仍拒绝，仅对尚无活动的目标档执行一次迁移。导入保留学习掌握与设置，原有外观作为体验展示收藏；旧钱包、分数和未验证奖励不会直接变成正式收入。当前账号已有学习、收藏或设置活动时拒绝覆盖，并保留双方数据。尚未提供活动账号合并。

网页可以导出当前服务器快照；导入摘要确认后才提交。恢复前副本只放在该页面内存，必须及时下载，刷新后不会保留。服务部署方还应自行备份SQLite，个人JSON导出不能恢复未完房间或登录凭据。

## 房间与部署

对战、队列和短期题目仍在单个权威进程内；服务重启结束未完对局。一个playerId最多占一个在线席位，重连同时要求Cookie身份和房间重连秘密匹配。同一账号的新连接替代旧连接；不允许同账号左右互刷。

服务端只发本人手牌，对方只见张数。参与者公开信息是游戏英文名、已出牌、生命和战斗结果，不公开另一方学习历史。无聊天、在线人数伪造或全服排行榜。

公开部署还需要稳定Node服务、HTTPS/WSS、持久数据库盘、备份与容量/滥用评估。GitHub Actions仅作临时测试，不能充当用户在线服务器。
