# Spellwood 权威服务器小规模容量实测

2026-10-08，助手云端本地测试。结论：在这一环境和短时动作模式下，10 / 20 / 50 个真实 TCP WebSocket 连接、5 / 10 / 25 个双人房间均完成了合法对局动作与 SQLite 持久写入，没有拒绝、写入错误或意外掉线。50 连接阶段服务器约 79 MiB RSS、约 39% 单核 CPU，动作 ACK p95 约 92 ms，但观察到约 329 ms 的最大 ACK 延迟和约 311 ms 的事件循环停顿。

这些是受控的约 10 秒阶段性实测，不能称为最大承载人数、长期稳定容量、真实浏览器并发人数或部署 SLA。初步支持小规模教师试用，再在最终部署机器上逐步验证实际浏览器、网络与历史存档。

CPU 百分比以一个逻辑核的 100% 为分母；RSS 仅列服务器进程，取阶段采样峰值与结束读数中较大者。所有延迟单位为 ms，RSS 为 MiB（2^20 字节）。

- 三阶段共 1,582 个成功游戏命令、400 个成功 HTTP 设置写入；400 条设置事件均由实际身份存储查询确认已记录。三阶段命令拒绝、HTTP 错误、意外 WebSocket 关闭均为 0
- 独立启动的空闲服务器：55.52 / 55.20 / 55.02 MiB RSS；每次观察 2 秒，CPU 约 0.8%–1.3% 单核。空闲窗口很短，含启动后的运行时活动，不能当作长期空闲平均
- 负载生成器为另一 Node 进程，CPU 约 5.6% / 13.4% / 17.5% 单核，采样 RSS 峰值约 65.9 / 68.5 / 78.0 MiB。它没有计入表内服务器 RSS/CPU，但与服务器共享测试机器，仍可能影响调度
- 整个成功容量运行耗时 49.787 秒，受控进程树的 100 ms 抽样 RSS 峰值 159.18 MiB，未触及 384 MiB 限额

## 测试如何运行

- 冻结工作树 HEAD：53425d2e7b5b5223cad93753ab727631d3a327ed；运行代码与 8f594ec 相同，两个提交之间仅文档和验收证据改变。server 树 d5264b00ed5f5d33369cb2492aac069b2e7a4676，src 树 ae3ff0e325410d691ccd199ebc486a7e31b53741
- 测量没有修改应用运行代码、访问生产站点或使用真实学生、真实账号及外部负载服务。当时工作树仅有说明文档待更新，不影响冻结的 server/src 源码；本报告和复现脚本现另行版本管理
- 每个阶段使用新的独立服务器进程，调用实际 createGameServer，只指定 127.0.0.1、随机空闲端口和临时 SQLite 文件；没有调高游戏速率限制或修改规则、时钟、AI、密码参数
- 数据库使用生产配置 WAL + synchronous=FULL。guest fixtures 由生产 IdentityStore.createGuest 创建，随后客户端凭真实测试 Cookie 走正常 WebSocket 身份验证与 session.open。这样测的是已有身份的在线负载；不绕过、关闭或测试“单 IP 每分钟 30 个新游客”的注册入口限制
- 每阶段先观察空闲 2 秒，再创建全部房间；每房间执行 4 个预热动作，总主动预热至少 1 秒，然后计量约 10 秒。初始建档、连接和配对不计入活跃阶段；未专门预热 HTTP fetch 连接，因此第一个阶段的 HTTP 端到端样本包含首次客户端初始化/连接成本
- 使用单一负载生成器，连接循序建立；每个房间串行发送动作，目标每 250 ms 一个动作，最多 25 个固定房间循环；同房间没有未确认命令并发。每房间每 4 个循环发一次 HTTP 设置写入，轮流使用两席身份，约每人每 2 秒一次
- 使用公开给客户端的手牌/场面选择合法出牌、攻击和结束回合；每 7 个循环尝试可用仪式，下一循环回答所显示的第一个选项，不读取私有答案。实际 50 连接阶段：264 次出牌、269 次攻击、193 次结束、135 次仪式开始、130 次仪式回答。部分房间在窗口末自然结束，没有人工篡改战斗状态
- 使用默认 school 题域、六年级/all/grove 配对。这测量生产权威栈，不是 teacher-academic 题目长度的单独比较
- 这些客户端是独立 Node 进程中的协议客户端，使用真实 TCP/HTTP/WebSocket。它们不是内存 mock，也不是 50 个浏览器或 50 位真实用户；未加载 WebGL、音频、图片和整个页面

## 样本规模与数据大小

50 连接时的 50 个新档最终每人平均 3.1 次学习回答、至多 4 个已见问题，线上成绩记录平均 0.04 条、至多 1 条。序列化进度 JSON 平均 1,684 字节、最大 2,220 字节。其他阶段也只有同量级的新档。

生产进度以整个 JSON 校验、序列化并写回。本次没有加入 100 题/几十场的中档历史，也没有重测已有约 6.54 MB 的大档样本；该大档数值来自外层已有容量回归，本报告没有独立复现。不能把本次新档的写入耗时外推到长期满档。

50 连接阶段收到 1,982 个房间快照，快照 JSON 平均 2,627 字节，p95 3,099 字节，最大 3,451 字节。WebSocket 接收载荷共 5,484,367 字节，约 0.536 MB/s（约 4.29 Mbit/s），这是该高频动作模式下全体客户端合计的服务器下行应用载荷；不含 TCP/WebSocket/TLS 帧头、HTTP 进度响应、图片、音频和页面资源。不能把它当作单用户日常带宽。

## 测量定义与边界

- ACK：负载生成器调用 ws.send 前至收到相同 commandId 的 command.ack；包含客户端/服务器调度和 localhost 往返
- HTTP 写入：发起 /api/progress/preferences 前至响应 JSON 读完；Cookie、Origin 和 X-Spellwood-Player 走生产校验，requestId 每次唯一。这包括网络栈、验证、整个进度运算、提交和响应，不是单纯磁盘时间
- SQLite 提交方法：只在基准外层包装实际 IdentityStore.commitPlayerEvent，调用前后读 performance.now，原方法完整执行。它含校验、JSON 序列化、事务、SQL、提交和回读，不能叫“裸磁盘 fsync 延迟”。三阶段该计时样本数分别 80 / 150 / 382，包含 HTTP 设置、游戏答题和自然结束结果；不含预热建档
- 持久化事件验证使用同一真实 SQLite 存储查询；没有在本次容量窗口之后重启服务器作额外断电/重启恢复试验
- 事件循环指标来自服务器 monitorEventLoopDelay，分辨率 10 ms。表中为该 API 原始间隔延迟，正常基线约 10 ms，不能理解成全部是额外排队时间。较大峰值可能来自应用/运行时/共享机器调度，本次不能单独归因
- RSS 为 100 ms 抽样和结束读数，可能漏掉瞬时峰值；仪表本身也有轻微成本。数据为单次短测，未做饱和点搜索、长时间稳定性、断线重连风暴、慢客户端、恶意流量、全档读写或 TLS 负载测试

## 单独密码/注册小样本

生产 scrypt 参数 N=32768、r=8、p=3，未降低工作量；使用实际 registerGuest（密码 scrypt、恢复码 SHA-256、会话更新与 SQLite 事务），没有 HTTP/浏览器开销。3 次顺序注册，无预热：831.52 / 419.36 / 355.11 ms；首个为冷启动样本。随后仅 2 个并发注册，分别 757.71 / 585.80 ms，总墙钟 758.61 ms。

单独注册进程空闲 RSS 38.48 MiB，10 ms 抽样峰值 103.39 MiB；保护包装器 100 ms 抽样峰值 104.31 MiB。只创建 5 个虚构临时账号，没有 50 个并发密码计算。样本过少，不报告可靠的分布或注册吞吐上限。注册/登录的内存和 CPU 成本应与已登录用户的游戏连接成本分开考虑。

## 环境与保护

Node v24.19.0；Linux 6.18.44 x64；操作系统可见 9 个逻辑 CPU，availableParallelism=9；可见总内存 10,451,460,096 字节（约 9.73 GiB）。/proc/self/cgroup 显示 0::/，此执行视图没有可读 cgroup mount、memory.max 或 cpu.max。可见资源不是分配承诺，也不能据此声称无限制或独占主机。

测量进程组使用384 MiB抽样内存保护和120秒总超时；保护器只管理本次新建的进程组。首次尝试有负载生成器的 WebSocket open 事件竞态，在活跃阶段开始前停住，由 120 秒保护器终止；其不完整数据未计入结果。修复后同一授权范围的重试完成，保留两次日志。它是测试工具问题，不是服务容量失败。

## 复现与文件

原始测量脚本绑定当时的冻结工作树。仓库另提供可移植 scripts/benchmark-server.mjs；运行时会在本机创建自己的临时服务和数据库，不连接生产服务器。必须在专用测试机或受控资源窗口执行，默认完整容量测量约一分钟。受支持的本地复现命令：

```sh
node scripts/benchmark-server.mjs
node scripts/benchmark-server.mjs --password
node scripts/benchmark-server.mjs --smoke
```

本仓库 evidence/server-capacity/2026-10-08 保存原始阶段 JSON、results.json 汇总、environment.json 环境及 password-results.json 密码小样本。首次不完整尝试的原因与排除方式已在上方说明；这些文件不含数据库、身份 Cookie 或账号凭据。
